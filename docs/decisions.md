# 設計決策與理由

這裡保存可隨 repo 維護的通用說明。各帳戶的原始需求、個別核准紀錄與修訂歷史，另由 misaki_context_query／misaki_context_commit 存在 D1。

## 使用 ChatGPT + Plugin → Site MCP → D1

使用者想直接在對話操作。模型已有教學及整理能力，Site 只需託管 MCP 與資料操作，D1 提供持久化。保留現有 Sites 平台整合，避免為整理 repo 同時更換部署技術。

## Raw、教材與練習分離

逐筆問答摘要不足以跨紀錄累積主題；因此以多對多來源維護 Wiki。Raw 保留原問答，教材可修訂，練習另存實際表現。需要刪除 Raw 時仍使用明確刪除流程，不以內容去重代替刪除。

## processed 只表達首次評估

使用者要求簡單判斷處理狀態，也說明舊資料仍可能與新資料重複或相似。因此保留布林值，但不把它解讀成永遠不必再看。評估結果與變更一起提交，避免已完成卻沒有結果。

## 彈性 Metadata、必要的一致性保護

自由 JSON 足以放標籤及筆記，暫不建立 Namespace 或通用工作流程。來源存在性、修訂號與重試需要確定性，保留交易、expected_revision 及 request_id 收據。相同請求可以重試，不同內容不能冒用同一 ID。

## 參考 LLM Wiki，但以日文學習為目的

[Karpathy 的 LLM Wiki 原文](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)提供保留來源、持續整合與維護知識的思路。本專案將它用於日文教材，不把原文當作學習效果的證明，也不必採用其全部工具。

反覆問相似句子可供選題參考，不能直接斷言不會；不同語氣、禮貌程度及場合不可只因字串相似就合併成等義。練習保存具體回饋，不計算假精確的熟練度。

## Repo 維護優先，重建文件附隨

程式、測試、需求及架構文件優先服務自己的維護。其他人的 ChatGPT 只需能讀懂並重建，所以提供清楚文件與 prompts/，不增設安裝器或自動升級服務。

帳戶綁定 manifest 不適合直接複製給其他帳戶。Repo 保存通用範本與指示來源；真正 Site／App／Plugin ID 由該帳戶建立或查回。
